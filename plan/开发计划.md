# DSH「最近会话」插件开发计划

## 目标与范围

在 DSH 主页左侧「工作区」列表的**最后一个工作区之后**增加可折叠的「最近」分组，汇总所有工作区的近期会话，便于跨项目查看正在运行或等待用户处理的会话并直接进入。插件设置页命名为「最近会话」。本仓库目前为空、尚未初始化 Git；从独立插件项目开始，不以修改 DSH 本体或复制整套侧边栏为默认方案。

## 已确认的接口边界

- 当前 `sidebar.workspaces` 是 **single** 插槽，已被原工作区浏览器占用；覆盖它会遮蔽原界面。现有子插槽仅面向单个会话的菜单、行尾按钮、行首装饰、悬浮卡和目录流程，**没有已确认的「工作区列表末尾」追加插槽**。
- Client `uiWorkspace.openSession(sessionId)` 是已确认的进入会话操作；实现时仍须核实列表所需的数据选择器、会话状态来源和组件/插槽的可复用方式。
- 禁止用 DOM 注入或 CSS 伪元素将「最近」硬塞到原工作区列表下，也不应冒充其他无关插槽。
- **接入前置关卡**：优先寻找现有版本可用的追加插槽；如确实不存在，则需评估由 DSH 上游增加专用 additive slot 的最小改动并说明版本依赖。仅在用户明确接受维护代价时，才考虑整体替换 `sidebar.workspaces`；不可默默复制工作区浏览器。

## 功能与交互

1. **位置与折叠**：在最后一个工作区下方显示「最近」标题。点击标题切换折叠/展开；折叠只隐藏内容，不改变会话数据。默认展开，页面刷新后的折叠状态可按现有 UI 偏好机制保存；若缺少机制，首版可仅保留本次页面状态并明确说明。
2. **汇总与排序**：覆盖所有工作区中正常可见的未归档会话；以最近聊天/活动时间降序排序，时间相同以稳定的会话 ID 保序，避免列表跳动。定义时间取值时与 DSH 原会话列表保持一致，不将单纯悬停或展开视为聊天活动。
3. **排序入口**：「最近」标题右侧保留可访问的排序按钮/选择器；首版只提供「最新」一个选项且默认选中，不虚构其他排序方式或无效切换行为。控件不能覆盖折叠点击区域。
4. **条目展示与跳转**：会话标题、截断、相对时间、运行转圈、等待干预的亮点、选中态等尽量复用原工作区会话行的组件和状态源，不能仅凭标题/最近时间推断运行状态。点击调用原有会话导航能力，切换到该会话正文；无需先人工切换工作区。
5. **所属项目提示**：鼠标悬停在「最近」中的会话上显示其所属项目/工作区名称；可复用原悬浮卡，若不合适则用轻量提示。保证键盘聚焦时也可获知所属项目。名称缺失时采用可识别的工作区名/路径后备值，不展示空白提示。
6. **显示条数与更多**：默认显示 10 条。实际条数超过设置值时出现「展开更多」，点击后展示其余会话，并可「收起更多」恢复到设置条数；不将“展开更多”误做只加载下一页。会话数量为零时显示适度的空状态。会话很多时应考虑分页/虚拟化或有界获取，避免逐个会话订阅和重复扫描。
7. **设置页**：「最近会话」页面至少包含默认显示条数（整数，默认 10，明确允许范围及无效输入反馈），修改后可保存并生效；设置页顶部动态标注**本插件仓库名称及其 Git tag**，不是当前聊天工作区名称，也不是写死的版本字符串。构建/打包时读取仓库元数据注入版本，安装后的包即使没有 `.git` 也能显示；无 tag 时明确显示未打标签及短提交号，完全没有 Git 信息时显示“未知版本”，不得伪造 tag。

## 实施步骤

### 阶段 1：建立仓库与查证

- 在空目录初始化 Git，建立 README、忽略规则、插件包清单、Host/Client 入口、中文显示文案、图标与最小构建流程。首个 tag 由发布时创建，不为满足界面展示而伪造 tag。
- 使用 `cordis_inspect_list` + 定向 `cordis_inspect_query` 查证当前版本的侧栏插槽及 props、工作区快照、会话状态及导航、设置页插槽/配置能力、主题 token；查看匹配的插件开发参考和现有工作区会话行实现。
- 形成短的接入决策记录：可追加插槽、必要的最小上游改动，或用户批准后的高维护替换方案；没有稳妥接入点时先报告阻碍，不写 DOM hack。

### 阶段 2：数据与组件

- 建立跨工作区的会话索引及最新排序，按稳定键去重，处理会话新建、重命名、活动更新、归档、工作区变更和删除。
- 复用原会话行渲染/状态语义；实现项目悬浮提示、键盘可达提示、会话导航和适度空状态。颜色、间距、图标和明暗模式沿用 DSH 设计 token 与模式。
- 加入折叠、「最新」排序入口、初始条数与“展开更多/收起更多”，避免横向溢出；排序入口仅一个选项，预留接口但不提前开发其他策略。

### 阶段 3：设置、版本及安装

- 实现「最近会话」设置页与显示条数的持久化/校验；根据设置即时更新显示数量。
- 在**构建时**从本插件仓库读取名称、Git tag 与必要的短提交号，产出随插件分发的元数据；明确“最后打的 tag”与“当前提交恰好处于某 tag”的区别，优先展示当前提交对应的 tag，未命中则显示未打标签与提交号。测试无 `.git` 的安装环境。
- 完成插件包元数据、中文标题/说明、原创图标、资源导出和配置说明；打包后按当前环境允许的方式安装/加载，不能把仅仅注册成功当作视觉验收。

### 阶段 4：最小验收与 Git 交付

- 手动验证：跨至少两个工作区的最新排序；点击跳转；运行转圈及待处理亮点随实际会话变化；折叠/展开；超过默认 10 条的更多/收起；修改显示条数后生效；悬停与键盘聚焦能看到所属项目；无会话/无 tag/无 `.git` 的回退；浅色与深色模式、窄侧栏。
- 仅针对排序/条数/版本回退等容易退化的纯逻辑写少量必要断言，避免依赖本机真实会话数据的重型测试。
- 检查 Git 变更并提交代码与说明。除非用户另行授权，不替用户推送远端、创建远端仓库或发布版本；如需要 tag，先说明 tag 名和目标提交再执行。

## 完成标准

插件安装后，「最近」确实位于最后一个工作区下面；原有工作区、搜索、会话操作不受破坏；跨项目会话排序和导航正确；运行/待处理状态与原列表同步；排序入口显示「最新」；项目名称提示可用；10 条默认限制与设置可生效；设置页顶部显示由本仓库 Git 元数据生成的真实版本标识；源码和使用说明保存在 Git 中。
